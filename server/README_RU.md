# Выделенный сервер Project Kingdom

Комплект запуска выделенного сервера Forge 1.20.1 / 47.3.0. Сервер — единственный
авторитет: он решает все расчёты, платежи и права, клиент только отправляет запросы.

## Состав

| Файл | Назначение |
|---|---|
| `server.properties` | конфигурация сервера: порт, белая списка, `sync-chunk-writes=true`, лимиты прав |
| `eula.txt` | шаблон лицензии; в репозитории `eula=false`, принять должен оператор |
| `start_server.sh` | установка Forge (один раз), копирование мода, запуск сервера |
| `backup_world.sh` | резервная копия мира вместе с журналом расчётов |
| `rcon.py` | минимальный клиент Source RCON для `save-off` / `save-all flush` / `save-on` |
| `restore_world.sh` | восстановление мира из архива: сначала проверка, текущий мир откладывается в сторону |
| `verify_backup.py` | проверка архива: мир, `level.dat` и целостность журнала расчётов |
| `settlement_admin.py` | разбор журнала расчётов оператором: состояния доставок и причины карантина |
| `validate_bundle.py` | проверка комплекта: конфигурация, синтаксис скриптов, протокол RCON |

Данные сервера (мир, библиотеки, журналы, резервные копии) лежат **вне репозитория**:
`server/run/` по умолчанию, переопределяется переменной `KINGDOM_SERVER_DIR`.

## Первый запуск

```bash
# 1. принять лицензию Minecraft (один раз, осознанно)
sed -i 's/eula=false/eula=true/' server/eula.txt

# 2. положить установщик Forge рядом со скриптом
#    forge-1.20.1-47.3.0-installer.jar  ->  server/

# 3. собрать мод
./01_build_linux.sh

# 4. проверить комплект
python3 server/validate_bundle.py

# 5. запустить
server/start_server.sh
```

Скрипт откажется стартовать, если лицензия не принята, если Java старше 17 или если нет
собранного мода. Мод копируется в `mods/` автоматически: клиент и сервер должны работать
на одной и той же сборке, иначе Forge отклонит соединение из-за протокола.

## Права и доступ

- `online-mode=false` — ванильная проверка сессии Mojang отключена, потому что вход идёт
  через лаунчер с одноразовым токеном (проверка токена остаётся в моде, `AuthGate`).
  Белый список при этом включён и принудителен: `white-list=true`, `enforce-whitelist=true`.
- `op-permission-level=4` — операторы получают полный уровень, обычные игроки — никаких
  команд (`function-permission-level=2`).
- `spawn-protection=16` — защита спавна; `pvp=false`, `spawn-monsters=false`.

Выдать оператора: в консоли сервера `op <ник>`. Белый список: `whitelist add <ник>`.

## Резервные копии

```bash
server/backup_world.sh
```

Копия — `server/run/backups/kingdom-<UTC>.tar.gz`, внутри `world/`. Журнал расчётов лежит
в `world/kingdom-settlement/` и попадает в архив вместе с миром: **мир без журнала
восстановить автоматически нельзя**, а журнал без мира бесполезен.

Если сервер запущен, скрипт требует RCON:

```properties
enable-rcon=true
rcon.port=25575
rcon.password=<длинный случайный пароль>
```

и переменную `KINGDOM_RCON_PASSWORD`. Тогда скрипт выполняет `save-off` → `save-all flush`
→ архив → `save-on`, не останавливая сервер. Если RCON не включён, скрипт требует
остановленного сервера и отказывается копировать «на ходу».

Старые копии удаляются через `KINGDOM_BACKUP_KEEP_DAYS` (по умолчанию 14 дней).

## Долговечность

`sync-chunk-writes=true` — каждый чанк сбрасывается на диск. Это то, что позволяет
доставке, уже записанной в журнал расчётов, пережить отключение питания вместе с миром.

## Восстановление

```bash
server/restore_world.sh server/run/backups/kingdom-<UTC>.tar.gz
```

Скрипт сначала проверяет архив (`verify_backup.py`): без мира, без `world/level.dat` или с
повреждённым журналом расчётов восстановление не начинается. Текущий мир откладывается в
`world.before-restore-<метка>`, поэтому неверный архив его не уничтожит.

## Журнал расчётов оператора

```bash
python3 server/settlement_admin.py server/run/world/data/kingdom_settlement/settlement-authority.log
```

Показывает состояния доставок, причины карантина и повреждения журнала. Код возврата
ненулевой, если журнал повреждён.

## Команды сервера

| Команда | Уровень | Назначение |
|---|---|---|
| `/settlement status` | 2 | состояние журнала: путь, размер, число доставок и карантина |
| `/settlement quarantine` | 2 | список доставок в карантине с причинами |
| `/settlement recover` | 4 | принудительное восстановление |
| `/settlement compact` | 4 | ужать журнал: готовая доставка остаётся одной записью |
| `/settlement resolve <uuid> applied\|not_applied` | 4 | решение оператора по карантину |

## Проверка комплекта

```bash
python3 server/validate_bundle.py
```

Проверяются: наличие и значения ключей `server.properties` (`sync-chunk-writes=true`,
белая списка, `online-mode=false`, уровни прав), что шаблон лицензии не принят заранее,
синтаксис и права исполнения скриптов, что каталог экземпляра не попадает в git, работа
RCON-клиента на поддельном сервере (кодирование и разбор пакета, аутентификация, выполнение
команды), разбор журнала расчётов на целом и повреждённом журнале, проверка архива
(полный проходит, без мира и с повреждённым журналом — отклоняется) и то, что
восстановление сначала проверяет архив и откладывает текущий мир в сторону.
