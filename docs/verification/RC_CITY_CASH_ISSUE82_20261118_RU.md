### Критический риск: aliasing касс

`KingdomPhysicalCash.move` проверяет `source != target` по ссылке. Два разные wrapper-объекта на один инвентарь обходят проверку; source/target планируются из одинакового исходного состояния, затем последовательно применяются. Потенциальный дюп на двух обёртках: 100 медных в общем инвентаре → после операции 200. Воспроизведение и независимое исправление — [Issue #86](https://github.com/kataev62-web/ProjectKingdom/issues/86). **Это логический контрпример по коду, не утверждение о подтверждённой эксплуатации на сервере.**

Дополнительные известные границы PR #76: `KingdomPhysicalCash.deposit/withdraw`, `PurseTransaction`, `KingdomEnterprisePayrollData.claimNpc` всё ещё могут пересоздавать номиналы; банк не имеет crash-atomic журнала для всех состояний. См. `ECONOMY_ARCHITECTURE_AUDIT_20261118_RU.md`. Эти модули здесь не меняем.
