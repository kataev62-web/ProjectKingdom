Новые проверки `KingdomIntegrationProfessionsSmokeTest`:
1. Лесоруб, шахтёр и животновод (`breeder`) имеют физический executor. Общий scheduler разрешает рабочую цель только днём при активном контракте и наличии задания; исполнитель отказывает без контракта или при защитном намерении.
2. `contractPaused` закрывает employed/hasAssignment всех трёх профессий до обращений к миру. Это проверка договорного шлюза, не симуляция движения к кассе.
3. Последовательность лесоруб → шахтёр → животновод с сериализацией/загрузкой SavedData сохраняет UUID/работодателя, паузу/неоплаченные дни, инструмент, количество и NBT груза, статус шахты. Это NBT round-trip, не рестарт настоящего сервера и не миграция одного типа предприятия в другой.
4. Выбор загруженной части загона #57 согласуется с общим assignment gate: выгруженный центр не блокирует загруженного соседа, полностью выгруженный загон не даёт рабочую цель. Предикат загрузки в тесте искусственный; чанки игры тест не загружает.

Кроме того, в объединённом прогоне сохранены регрессии #56 по реальной логике записи груза и отказам/частичному приёму контейнера, смене инструмента и сохранению долгов; регрессии #57 по границам загона, TFC-кормлению и безопасности забоя. Проверки исходных подстрок не выдаются за физический игровой тест.

## Анализ общей логики и предупреждений
- `KingdomNpcMod` и `KingdomNpcWorkday` не изменены ни интеграцией, ни новыми тестами. Общая смена использует employed → hasAssignment → GoalSelector → profession executor. В #56 готовое физическое задание запускается также для лесоруба/животновода; #57 предоставляет животноводу точку в загруженной части загона. Противоречий на уровне проверенных контрактов не обнаружено.
- Производственные изменения принадлежат исходным PR. Новые изменения этой задачи — только тесты и этот отчёт; самостоятельных исправлений бизнес-логики нет.
- javac предупреждает о deprecated API; Gradle — об устаревающих возможностях, несовместимых с будущим Gradle 9.0. Текущий Wrapper 8.8 успешно завершает сборку; обновление Gradle не выполнялось.
- TFC API подключён через runtime/reflection, а не обязательную compile dependency. Успех ForgeGradle/JUnit не доказывает наличие/совместимость реального TFC или Create. PR #57 использует публичный `ICalendar` при reflection; его вызов в реальном модпаке не проверен.
- На этом стенде в `/workspace` не обнаружены JAR TFC/Create или `level.dat` копии мира. В build.gradle нет фиксированных runtime-зависимостей этих модов. Поэтому выделенный сервер с полным модпаком не подготовлен и не запускался; даже Forge-only runtime smoke здесь не заявляется. EULA не принималась, неизвестные версии модов не подбирались.
- Журналы текущей среды: `/workspace/.cloud-setup/reports/issue60/`; штатные JUnit XML/HTML — `build/test-results/test` и `build/reports/tests/test`. Эти локальные пути не заменяют независимый CI.
