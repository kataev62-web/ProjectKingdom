# Как проверить архитектора (Forge 1.20.1)

Сборка GitHub Actions: [workflow](https://github.com/kataev62-web/ProjectKingdom/actions/workflows/build.yml). Проверка компиляции и JUnit не является проверкой картинки в самой игре.

## Установка

1. Сделайте резервную копию тестового мира. Не устанавливайте пробную версию в единственный оригинал Авалона.
2. Скачайте JAR из артефакта `kingdomnpc-stage0` для последнего **успешного** коммита main и замените предыдущий `kingdomnpc` в `mods`.
3. На выделенном сервере и на клиенте должен быть **один и тот же** JAR, иначе Forge-соединение будет отклонено из-за нового сетевого протокола.
4. Версия игры — Minecraft Java 1.20.1, Forge 47.3.0. Для TFC/Create/Chisel/Domum Ornamentum схем требуются соответствующие установленные моды.
5. Сторонние файлы схем надо положить в папку конкретного сохранения `<world>/data/kingdom_schematics/<name>.schem` (имя латиницей, числа, подчёркивания, дефисы). Загружает сервер, а не клиент. Не путать эту папку с `WorldEdit/schematics`.
6. Импортируются Sponge `.schem` v2/v3, ограничение **48×48×48**, 65 536 блоков объёма и 2 МиБ сжатых данных. Старый `.schematic` не поддерживается напрямую; отдельные схемы могут отклоняться, если содержат двери, кровати, жидкости, сыпучие блоки или недоступные модовые блоки.

## Проверка в Minecraft

1. Установите или найдите **чертёжный стол** (`kingdomnpc:drafting_table`) или старую кафедру. Он должен находиться на своей территории, а игрок — не дальше четырёх блоков при выборе проекта.
2. ПКМ по столу обычной рукой → меню **Архитектор** → выберите встроенный тип дома или файл `.schem` из списка.
3. Включится графическое окно управления, а в мире появится модель: X±1/X±10, Z±1/Z±10, Y±1 и поворот на 90°.
4. Нажмите **Осмотреть**, чтобы походить вокруг. Клавиша **F8** возвращает кнопки управления при открытом мире.
5. Нажмите **Отменить**: ни один строительный блок не должен появиться, расхода чертежа быть не должно.
6. Повторите выбор, установите новую позицию, возьмите один предмет `building_blueprint` (в выживании), нажмите **Подтвердить**.
7. При невалидном участке (чужая земля, контейнеры, незагруженные чанки, старый проект) подтверждение должно быть отклонено; если всё допустимо — проект появится в списке. Настоящие строительные блоки пока не появляются.
8. Поставьте рядом с чертёжным столом сундук с настоящими материалами, наймите NPC-строителя и запустите стройку в меню проекта. Молот ставит следующий блок по старому механизму. NPC работает по той же очереди.
9. Выйдите и снова войдите в мир: проект должен запомнить строительный стол, расположение здания и поворот; NPC должен брать материалы из того же сундука.
10. Проверьте сохранение старой стройки, у которой нет полей `MarkerX/Y/Z`.

## Известные ограничения тестовой версии

- Превью передаёт до **2400 поверхностных блоков** для ограничения FPS и размера сети. Это не полноценный рендер всех интерьеров больших зданий.
- Цвет подсветки не является серверной оценкой прав и столкновений; **окончательное решение принимает сервер при подтверждении**.
- Системы анимированных строительных лесов, полноценный 3D-просмотр карточек в отдельном каталоге, разбивка огромных `.schem` на модули и автоматический набор одобренных схем ещё не включены.
- Реальное отображение прозрачности, ориентации сторонних блоков, расположение фундамента и реакцию интерфейса на модпак необходимо подтвердить на клиенте — автотесты этого не делают.

## Архитектура

- `KingdomArchitectClient` / `KingdomArchitectScreen`: клиентская модель, интерфейс и осмотр.
- `KingdomArchitectSessions`: отдельный временный серверный сеанс, токен, ограничение времени, привязка к исходному чертежу.
- `KingdomSiteBuilder.placeAt`: проверка всех запланированных блоков и регистрация строительного заказа.
- `KingdomConstructionData`: сохранение отдельной позиции строительного стола, совместимость со старыми мирами.
- `KingdomConstructionWork` и `KingdomNpcBuilder`: прежнее пошаговое строительство за реальные материалы.

**Никаких WorldEdit paste и прямых массовых setBlock в этой системе предпросмотра нет.**
