# Кузница TFC — физические заказы (Issue #68)

Основа: PR #66, Forge 1.20.1 / Java 17 / TerraFirmaCraft 1.20.x.

| Изделия | Натуральный путь TFC | Состояние |
|---|---|---|
| Головки инструментов (кирка, топор, лопата и др.) | Реальный металл из сырьевого сундука → CharcoalForgeBlockEntity (нагрев) → AnvilRecipe на AnvilBlockEntity (молот) → готовый сундук | Реализована обработка доступного native `AnvilRecipe`; нужен игровой smoke |
| Клинки оружия, металлические детали | Тот же native AnvilRecipe из металла, допустимого для тира наковальни | Реализован механизм, но номенклатура зависит от установленных TFC-рецептов/материалов |
| Слитки, сплавы из руды | TFC-тигель/горн, жидкий металл, реальные формы, охлаждение, извлечение слитка | **Не реализовано в управляемом заказе**: нет безопасного автоматического native casting pipeline |
| Сварка двух заготовок | Native AnvilBlockEntity.weld с нужным флюсом и двумя входами | **Не реализовано**; отдельная задача |
| Готовый инструмент (головка + палка) | TFC-сборка по настоящему crafting-рецепту | **Не реализовано**; кузница производит именно результат нативного anvil recipe, обычно головку |

## Использование
1. Создать кузницу, зарегистрировать комнату, установить действительное ядро, TFC charcoal forge и TFC anvil на собственной земле.
2. Нанять кузнеца; автонастройкой привязать реальное рабочее место, сырьевой и готовый сундуки; проверить трудовой договор.
3. Положить настоящий металл/заготовку, допустимую для `AnvilRecipe` (по тиру), настоящее TFC-топливо в сырьевой сундук, настоящий молот в слот наковальни.
4. Блок кузницы → **Производство** (либо «Заказы») → **Заказы кузницы TFC**. Выбрать рецепт из реальных доступных в складе `AnvilRecipe.getAll` и количество 1–64 → «Сохранить заказ».
5. Включить приказ NPC «Работать», соблюдать время работы, обеспечить еду/зарплату. Состояние обновлять кнопкой «Обновить». После ковки реальный предмет поступит в готовый сундук.
6. Прогресс увеличивается **только после физической доставки**. Новое изделие не запускается, пока предыдущее остаётся в наковальне.

## Проверки в Minecraft (обязательно перед merge)
- Сделать 1 головку кирки или клинок из существующего TFC-слитка: после заказа в сырьевом складе стало меньше исходных предметов; кузнец реально нагрел металл и выполнил шаги `AnvilBlockEntity.work`; тот же предмет с NBT из наковальни попал на готовый склад; прогресс 1/1.
- Заказать 3 одинаковых изделий: счётчик увеличивается по одному после каждого перемещения на склад.
- Заполнить готовый склад: готовое изделие остаётся в наковальне, счётчик не увеличивается; после освобождения места завершается доставка.
- Перезагрузить мир, когда металл находится в горне или когда готовое изделие ожидает места: заказ, фаза, счётчик и реальные предметы не теряются и не дублируются.
- Убрать молот/топливо или сырьё: статус блокировки, нет бесплатных продуктов; добавление настоящих материалов возобновляет работу.
- Второй NPC, чужая территория, выгруженный чанк, перенесённое ядро, неподходящий тир наковальни и попытка смены рецепта на активном заказе: нет работы или выдачи чужих изделий.
- Приостановить и продолжить заказ: TFC инвентари сохраняются, прогресс не перепрыгивает.

## Ограничения
- Один открытый заказ на кузницу, назначенный одному реальному кузнецу. Следующий заказ только после полной доставки предыдущего.
- Переключение рецепта в меню NPC запрещено, пока у кузницы активный заказ.
- Отдельные TFC-API доступны через reflection только если установлен TFC. Не предполагаем наличие горна, склада, молота или материалов без реальной проверки.
- Доступные JUnit/CI проверки не подтверждают фактический gameplay-процесс ковки. Перед merge требуется ручной запуск Forge+TFC на копии мира.

## Независимая ревизия Codex #84 — исправления безопасности

- **TFC 3.2.26 в production Forge 47.3.0:** `AnvilRecipe.getId` на реальном `TransformingClassLoader` отображается как `m_6423_`. Код обращается к идентификатору через `net.minecraft.world.item.crafting.Recipe<?>.getId()` (ForgeGradle-remapped invocation), а не через рефлексию по `getId` на классе TFC.
- **Консервация:** вместо изменения `getItem()` используется `Container.removeItem` с проверкой реального остатка; forge setter проверяется до извлечения сырья. Переносы между TFC-слотами подтверждают содержимое обеих сторон.
- **Доставка:** запись в склад проверяет точные count/item/NBT и пределы размера стека из PR #74; прогресс заказа учитывается только после проверенного освобождения нативного слота наковальни. Неудачная операция не считается доставкой.
- Добавлены четыре воспроизводимых теста Codex из `validation/pr72_review/KingdomSmithyPhysicalTransferReviewTest.java`, три проверки PR #74 и отдельные поведенческие тесты отказов нативных setter/getter.
- **Ограничение:** два независимых сторонних инвентаря не являются атомарной базой данных. Для аварийного выключения непосредственно между сохранениями двух BlockEntity необходим игровой crash/restart-аудит; поведенческие JUnit не являются доказательством абсолютной crash-consistency.
