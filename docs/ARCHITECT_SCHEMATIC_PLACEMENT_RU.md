# Архитектор: выбор, предпросмотр и заказ строительства

**Статус:** утверждённое поведение (ТЗ), по состоянию на 23.10.2026. Это НЕ описание готовой клиентской функции. Реализованная в текущем коде основа: `KingdomMainMenu.openArchitect`, `KingdomSchematicLibrary`, `KingdomSiteBuilder`, `KingdomConstructionData`, `KingdomConstructionWork`, `KingdomNpcBuilder`. Её необходимо сохранить, не заменяя на WorldEdit paste.

## Игровой сценарий

1. Игрок с соответствующими правами подходит к **блоку строителей / чертёжному столу** и открывает страницу **Архитектор**.
2. Открывает **каталог построек**. Карточка: настоящее изображение здания, имя, автор, размеры X×Z×Y, количество блоков и материалов, моды/лицензия, вход, назначение, метка проверки.
3. Выбирает здание → **Предпросмотр**. Это не стройка: никакие блоки/инвентари не изменяются, чертёж не расходуется.
4. В мире появляется **полупрозрачная 3D-проекция** здания с реальными моделями блоков и силуэтом. Архитектор видит её от первого лица, может свободно ходить вокруг, менять уровень, перемещать по X/Z/Y, вращать по 90° (0/90/180/270), отменить. В меню миниатюра-изометрия с вращением и кнопка «Выйти для осмотра».
5. Проекция подсвечивает место: **зелёный** — допустимо; **жёлтый** — требуется безопасная локальная расчистка/подпорка; **красный** — чужие права, существующий проект, защищённый блок, выгрузка чанка, выход за границы мира или запрещённая схема. Отображаются вход, ориентация, фундамент, уровень пола, расстояние до дорог.
6. **Подтвердить положение**: сервер повторно проверяет схему, целостность и хеш frozen snapshot, права на каждый блок, границы, препятствия, пересечение с проектами, маркер и склад. При успехе — и только тогда — списывает один строительный чертёж и сохраняет точные origin, rotation, dimension, marker, owner, design digest.
7. Возникает **PLANNED-проект**, а не мгновенная постройка. Архитектор/владелец решает, когда начать, назначает NPC-строителей и обеспечивает материалы через соседний склад. В меню показываются `required / available / missing` с реальными предметами.
8. Строители используют **имеющийся** `KingdomConstructionWork.placeNext`: проверяют права и склад, ставят реальные блоки по одному, работают в загруженных чанках, сохраняют прогресс и не создают предметы из воздуха. Строительный молот работает на том же проекте.

## Технический контракт

- **Никакого** `//paste`, `setBlocks` для строительства, творческой эмиссии ресурсов и безусловной очистки площади.
- Модель данных: `PreviewSession(playerUUID, schemaId, sourceSha256, dimension, markerPos, originPos, quarterTurns, expiry)` — эфемерна, НЕ SavedData, ограничена по игрокам, TTL/радиусу/количеству блоков. При выходе, смене измерения или отмене очищается.
- Преобразование: размещение X/Z с четвертью оборота, вращение `BlockState.rotate(Rotation)` для ориентации лестниц/брёвен/декора, без потерянных свойств. Квадратные и прямоугольные здания правильно меняют стороны на 90°.
- Авторитет: клиент получает **только визуальную копию**, вся проверка, выбранная схема, смещения и подтверждение на стороне сервера. Никакого trust к NBT/пакетам пользователя.
- Для осмотра проекта клиент получает ограниченные, сжатые chunk-partials/батчи палитры для рендера без форсирования чанков, с отсечением невидимого. Отдельный приоритет — контур/силуэт при крупных схемах.
- `.schem` из каталога — импорт в мир только после проверки лицензии, формата и разрешённых blockstates. Сторонний проект не исполняет код.
- **Предел текущего импортёра:** 48×48×48 и 65 536 блоков объёма. Крупные замки/колизеи — отдельная задача безопасных модульных схем и сохраняемого общего проекта, не обходить лимит.
- Метаданные строительной площадки хранят **два разных якоря**: чертёжный стол/склад/бригаду и свободно выбранное расположение здания. Старые проекты без новых полей должны мигрировать: `marker = origin - (2,0,2)`, `rotation = 0`.
- Не менять `KingdomConstructionData.progress` и упорядоченный массив шагов после начала стройки. Схема замораживается перед созданием, последующая правка исходника не меняет уже выполняемый заказ.
- Предварительная проверка поверхности — *информационная*, финальная в момент подтверждения атомарная на главном серверном потоке с защитой от повторного нажатия.
- Разграничить «архитектор может проектировать» и «владелец/уполномоченный может утверждать строительство» согласно KingdomCivicsData; замысел не даёт обхода территориальных прав.
- Не подменять полноценный 3D-просмотр точками-частицами. `KingdomConstructionPreview` остаётся полезным для подсказки следующего блока **во время** строительства, но это не предпросмотр архитектора.

## Критерии приёмки

- Архитектор из меню открывает настоящую карточку схемы с изображением и размерами.
- В клиенте Forge 1.20.1 виден объект целиком с правильными текстурами; нет «коробки» или только линии из частиц.
- Без установки конструкции можно сдвинуть на 1 блок, повысить/понизить и повернуть 4 раза; прямоугольная схема меняет X/Z местами при 90°.
- Лестницы, плиты, столбы, декор Create/TFC поворачиваются правильно либо явно блокируются как не поддерживаемые.
- Отмена не изменяет мир и не расходует материалы.
- Подтверждение при пересечении чужого участка, сундука, другого проекта, неизвестном моде или недогруженной зоне отклоняется без частичных списаний.
- После подтверждения можно начать/остановить NPC, посмотреть ведомость, собрать материалы, строить молотом; перезапуск сервера сохраняет позицию и поворот.
- Не сломаны старые проекты, созданные до режима предпросмотра.

## Зависимости реализации

1. Геометрия X/Z и ориентации blockstate, тесты 0/90/180/270 (базовый подготовительный компонент).
2. Persisted marker/origin + migration и frozen rotated plan.
3. Server-side preview session + bounded palette packets + client-side ghost renderer, отображение карточек.
4. UX кнопок перемещения, вращения, подтверждения и отмены.
5. Серверная транзакция подтверждения и регрессионные тесты со строителем, ведомостью, безопасной расчисткой.
6. Smoke test на реальном Forge 1.20.1 и разных фактических модовых схематиках; только после этого перевод в «готово».
