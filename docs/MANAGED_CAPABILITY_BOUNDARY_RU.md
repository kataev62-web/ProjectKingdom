# Защищённый Forge IItemHandler — этап 1

`TradeGuardedItemHandler` оборачивает `IItemHandler` зарегистрированного предприятия. Все операции insert/extract, включая simulate, проходят через `TradeManagedInventory.mutate` под тем же монитором, что и торговые блокировки. При отказе вставка возвращает исходный предмет, извлечение — пустой стек. Чтение возвращает копию ItemStack.

## Ограничения и необходимые действия

1. Блок предприятия должен выдавать **только** защищённый обработчик через `ForgeCapabilities.ITEM_HANDLER` и не публиковать исходный `ItemStackHandler`/`Container` через другие API.
2. При выгрузке блока capability нужно инвалидировать (`LazyOptional.invalidate()`), при загрузке восстановить привязку к предприятию из постоянных данных.
3. Не следует автоматически подключать этот адаптер к обычным сундукам: их ванильные пути доступа обходят capability.
4. Запись из торгового координатора под lease требует отдельного внутреннего пути (`TradeManagedInventory.project`), который нельзя раскрывать автоматизации.
5. Для реального защищённого блока остаются реализация BlockEntity, регистрация блока и инвентаря, серверные проверки прав, тесты в Forge с воронками/Create.

Новый адаптер не делает сохранение двух BlockEntity атомарным и не заменяет журнал/сверку.
