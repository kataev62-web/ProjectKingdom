# Архитектура игрового ядра Stage 0

## Цепочка входа

1. Лаунчер получает одноразовый токен внешней платформы.
2. Серверный адаптер передаёт токен в `AuthGate`.
3. `AuthGate` проверяет подпись через подключаемый `TokenVerifier`, срок действия и отсутствие повторного использования.
4. Подтверждённый `AccountId` передаётся в `IdentitySavedData`.
5. Для нового аккаунта создаются единственные `CharacterId` и `DynastyId`; при следующих входах меняется только UUID сессии Minecraft.
6. До допуска игрока выполняется `MigrationGate`.
7. На первом входе `SpawnResolver` выбирает Avalon либо безопасный обычный спавн.
8. `KingdomBookGuardian` гарантирует одну постоянную Книгу игрока.

Сетевой адаптер между внешним лаунчером и Forge не входит в Stage 0: контракт создан, а производственный проверяющий токенов по умолчанию отключён.

## Книга игрока

| Раздел | Состояние Stage 0 | Источник |
| --- | --- | --- |
| Игрок | активен | идентичность персонажа |
| Банк | активен | `KingdomBankData` |
| Капитал | активен | банковский баланс + физический кошелёк |
| Государство | заглушка | подключается отдельным этапом |
| Династия | заглушка | подключается отдельным этапом |
| Мир | заглушка | подключается отдельным этапом |

Книга восстанавливается при входе, возрождении и смене измерения. Выбрасывание отменяется. Лишние экземпляры удаляются. Предмет привязывается к владельцу.

## Расширение без переделки ядра

- `ModuleRegistry` запускает игровые модули независимо и переводит сломанный модуль в состояние `FAILED`.
- `CoreServices` задаёт общие контракты событий, разрешений, feature flags и аудита.
- `PaymentProvider` является отдельной границей; заглушка возвращает `provider_not_configured` и не меняет баланс.
- `Stage1FinanceAdapter` только читает существующую экономику, не создавая второй денежный контур.

Так новые этапы смогут подключать реальную механику к готовым разделам Книги, не меняя идентичность игрока и не связывая всё ядро в один неустойчивый модуль.
