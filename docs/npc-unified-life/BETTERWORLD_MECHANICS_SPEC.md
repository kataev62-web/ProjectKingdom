# Самостоятельное развитие жителей

Референс — BetterWorld (Village) 1.2.3 Forge 1.20.1 из клиентского профиля владельца. [Modrinth](https://modrinth.com/mod/betterworld-village/version/GTVKkD2T) публикует JAR, описание и MIT. Поле source_url API пустое. Ни официальный репозиторий, ни документированный интерфейс подключения к MCA не установлены. Названия ниже сверены с классами JAR и служат ориентиром для реализации. Они сами по себе не доказывают готовность поведения.

| Механика | След в 1.2.3 | Контракт Kingdom |
| --- | --- | --- |
| Смена профессии и карьера | WorkRegistrationGoal, отдельные цели профессий | Резидент с опытом и навыками оценивает доступные вакансии. Действующий договор меняется через существующую процедуру найма. История и долги сохраняются. |
| Владение предприятиями | WorkOwnership, OwnershipType, TownAssetCustodyService | Покупка или основание через существующий реестр предприятия и право на здание. Расчёт идёт с личного счёта, актив и прибыль учитываются отдельно от работодателя. |
| Экономическая инициатива | ArbitrageTradeGoal, MarketDemandRegistry, ResourceBuyInputsGoal, ResourceSellProductsGoal | Хранимые намерения закупки и реализации с остатком на складе, лимитами цен и резервом средств. При ошибке резервы освобождаются. |
| Личные цели | NeedAwareGoalPriority, FoodSupplyGoal, HomeRegistrationGoal, OwnerLeisureGoal | Периодическая оценка потребностей и целей по UUID. Семью, обычный отдых и поведение вне смены ведёт MCA. Действия Kingdom дают предложения с кратким сроком. |
| Расширение поселения | TownStarterSettlementService, ConstructionProcurementGoal | Сформировать заявку на здание по демографии и дефициту помещений. Применить штатные полномочия, резерв земли, физические ресурсы и реестр строительства. |
| Самостоятельные покупки | PersonalShoppingGoal, BudgetPolicy, PurchaseElasticity | Проверка кошелька, цены, объёма, минимального резерва бюджета и доступа. Покупка списывает только реально зарезервированные деньги и передаёт реально доступный товар с NBT. |
| Наследование | InheritanceService, SteveEntity и семейные данные | Получить родных из MCA, активы из Kingdom. Уникальный ID дела на одну смерть, один перевод каждого актива. Имущество без подтверждённого наследника остаётся в наследственной массе до правил поселения. MCA управляет физическими death drops. |

Мод регистрирует собственную SteveEntity и свою модель владения. Для единого населения применяется собственная реализация на контрактах Kingdom. На чистом выделенном Forge 47.3.0 версии 1.2.3 и 1.2.8 упали на CONSTRUCT. JavaFML ищет BetterWorld.<init>(), а JAR предоставляет только BetterWorld(FMLJavaModLoadingContext). Не менять Forge Kingdom ради этой зависимости. Для версии 1.2.8 атрибут Implementation-Title указывает Forge 47.4.10 MDK. Это ориентир для отдельного эксперимента с ABI загрузчика, условия совместного мира на нём не доказаны.

Достаточный первый сценарий — взрослый житель MCA приобретает нужный предмет в пределах бюджета, получает зарплату из средств работодателя, повышает квалификацию за подтверждённую работу, получает предложение другой вакансии, формирует заявку на новое помещение. При смерти наследство закрепляется за членом семьи MCA после сохранения, рестарта и повторной обработки события. Два жителя не могут одновременно получить одну вакансию, лот или объект имущества.
