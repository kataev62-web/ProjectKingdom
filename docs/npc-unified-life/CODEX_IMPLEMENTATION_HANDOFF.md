# Передача Codex — единая система жителей

Возьми research/npc-unified-life, создай отдельную ветку разработки от неё и реализуй единый функционал одной поставкой. База исходников этой ветки 407f68f330da2c1572a6a3c94a526e9dcb8ccc66. Исследование закрепляет Gradle 8.8, ForgeGradle 6.0.54, Minecraft 1.20.1, Forge 47.3.0, Java 17, TFC 3.2.26, Create 0.5.1.j, Patchouli 85, MCA 7.6.23 и Architectury 9.2.14. PlayerEngine и Player2NPC 1.4.0 доступны в исследовательских профилях. BetterWorld 1.2.3 — референс. Точные URL, SHA и оговорки даны в [манифесте](DEPENDENCY_MANIFEST.md) и [таблице совместимости](COMPATIBILITY.md).

1. Воспроизведи окружение командами из манифеста. Установленные JAR должны совпадать с lock-файлом. Зафиксируй прохождение базовой сборки. Сравни реализацию с точными классами MCA и Kingdom, указанными в [спецификации MCA](MCA_ADAPTER_SPEC.md) и [архитектуре](NPC_INTEGRATION_ARCHITECTURE.md).
2. Подключи существующих жителей MCA. Дай существующим работодателю, контракту и месту работы ссылаться на UUID MCA. Сохрани MCA Brain, личность, семью, инвентарь, штатное взаимодействие и свободное время. Добавь в меню MCA «Работа», «Зарплата» и доступ к физическому инвентарю по правам. Перейди на одну серверную диспетчеризацию смены, приоритет аварий MCA и контролируемую навигацию на площадке. В карту MCA подключи режим обследования помещения, валидация закрепления здания и прав остаётся у Kingdom.
3. Реализуй реальные серверные действия из [спецификации исполнителя](PLAYERENGINE_ADAPTER_SPEC.md). Используй MCA navigation, физические слоты, Forge hooks, TFC, контейнеры, сохранение мира и контроль территории. Реализуй шахту 7×7 с проходкой слой за слоем, инструментами по блокам, линией спуска, лестницей, безопасным креплением, настилом и уровнями через пять блоков, фактической логистикой. Текущий обход KingdomMineCentralShaftPlan используй как материал для миграции, а не как подтверждённый алгоритм. Остальные профессии должны сохранить рабочие пути TFC и экономические контракты.
4. Подключи безопасный Player2 Planner за независимым интерфейсом, выключенным по умолчанию. Реализуй локальный планировщик и проверь полный цикл без сети. Предложения внешнего API ограничены доменными намерениями. Используй [спецификацию развития](BETTERWORLD_MECHANICS_SPEC.md) для карьеры, собственности, инициативы, покупок, поселений и наследования. Тестируй оба профиля, с провайдером и без него, через заглушку до интеграционного вызова реального API.
5. В миграции используй резервную копию мира владельца. Переходы связывать по подтверждённым UUID, хранить версию схемы и состояние переноса, восстанавливать с реальным остатком. Обработать выгрузку, смерть, превращение и рестарт, избегая повторной зарплаты и наследования. 7.7 beta включается только в отдельном сравнительном профиле. В новом мире один MCA-житель получает один профиль Kingdom, один физический инвентарь и не создаёт NPC сторонних модов.

## Одна приёмка перед передачей JAR

- Запускаются clean test build и выделенный сервер core с собранным Kingdom. В релизный набор попадают проверенные зависимости, журналы запуска и SHA-256 JAR.
- В копии мира сохраняются UUID, семья, имя, профессия, инвентарь с NBT, помещение и принадлежность после рестарта. Уполномоченный игрок назначает работу из меню MCA, кладёт инструмент, платит зарплату; другой игрок получает отказ без побочных изменений.
- Шахтёр реально извлекает грунт лопатой, породу киркой, полностью завершает допустимый слой и спускается до следующего уровня. Тестируются отсутствие инструмента, чужой участок, отменённый Forge BreakEvent, жидкость, отсутствие опоры, блок недоступен, заполненный склад, повторная загрузка и целостность инструментов/добычи.
- Смена не запускает конкурирующее движение и освобождает точку работы при отдыхе, панике и выгрузке. Фермер использует семена и существующие растения TFC, урожай перемещается физически и доступен тому же зарегистрированному складу.
- При рестарте и повторном оформлении нет дублирования активов, монет, выплат, NBT и записей наследства. Смена карьеры сохраняет всю историю. Плохой ответ Player2 не меняет мир и сервер завершает смену локально.

Правки исходного сервера владельца и слияние main после реализации требуют отдельного решения владельца.
