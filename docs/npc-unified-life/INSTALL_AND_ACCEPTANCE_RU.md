# Проверка NPC: финальная интеграционная RC

Ветка `codex/npc-final-integration`, база MiniMax `3e4d2d7`, включая исправления Ники PR #106.
Это кандидат для проверки на копии мира. Полная игровая приёмка пока не подтверждена.
Точный коммит и SHA-256 JAR находятся в `COMMIT.txt` и `SHA256SUMS` рядом с JAR
в артефакте GitHub Actions `kingdomnpc-rc-<SHA>`. Не используйте старый SHA из отчёта MiniMax.

## Установка

Java 17, Minecraft 1.20.1, Forge 47.4.10. На клиент и тестовый сервер установить одинаковые версии:

| Мод | Версия |
|---|---|
| Project Kingdom | JAR из артефакта этого PR |
| Minecraft Comes Alive Reborn | 7.7.1-beta.5 |
| Townstead | 0.8.0 |
| TerraFirmaCraft | 3.2.26 Forge |
| Patchouli | 1.20.1-85 Forge |
| Create | 0.5.1.j |

Townstead получает бытовую жизнь вне смены. Во время работы Kingdom его конкурирующие рабочие задачи
и диспетчеризация приостанавливаются; настоящая аварийная усталость/обморок освобождает смену.

Исходные URL и SHA зависимостей закреплены в `dependencies.lock.json`.
PlayerEngine, Player2NPC и BetterWorld для этого набора не нужны; внешний планировщик по умолчанию выключен.
Не помещайте JAR `runtime-validation` и `runtime-validation-agent` в `mods`: это отдельные инструменты тестирования.

1. Остановить тестовый сервер, сделать резервную копию всего мира, включая `data` и `entities`.
2. Удалить предыдущий Kingdom JAR из `mods`, установить один новый JAR и перечисленные зависимости.
3. Проверить `sha256sum -c SHA256SUMS` (Windows: `Get-FileHash <JAR> -Algorithm SHA256`).
4. Запустить обычный выделенный сервер Forge на Java 17; для реального сервера оставить `online-mode=true`.
   MCA проверяется в production Forge, а не через `gradlew runServer`.
5. До переноса рабочего мира выполнить пункты ниже на отдельном мире.

## Короткая игровая проверка

1. Оператор: `/knpc spawn miner`. Убедиться, что создан `mca:male_villager` либо `mca:female_villager`.
   Существующего MCA-жителя можно зарегистрировать через Shift+ПКМ; сохранить его UUID для сверки.
2. Через меню Kingdom открыть инвентарь NPC, положить настоящие кирку и лопату с заметной прочностью/NBT.
   Окно MCA и Kingdom должны показывать одну сумку. Закрыть окно перед проверкой работы.
3. Зарегистрировать предприятие «Шахта», права на землю, ядро, действующий договор с NPC,
   участок 7×7 и склады сырья/готовой продукции. Положить инструменты, лестницы, настил и опоры TFC в склад сырья.
   Не создавать бесплатный контракт или виртуальные ресурсы ради обхода проверок.
4. `/knpc schedule`: дождаться индивидуальной активности `WORK` MCA (у дневного жителя обычно 2000–9000,
   у ночного — 15000–18000; назначенный график может отличаться). Наблюдать добычу горизонтального слоя до следующего,
   установку лестницы, физические дропы, износ, перенос на склад. Повторить с грунтом, натуральной породой и рудой TFC.
   Полный склад, вода, отсутствие опор/инструментов/пути и чужая земля должны останавливать действие с причиной.
5. Проверить жителя днём и ночью: работать он должен только в своём периоде `WORK`; в `MEET/IDLE/REST`
   управление возвращается MCA. При энергии ≤25 работа прекращается, при наличии безопасного пути шахтёр
   выходит к входу; после фактического отдыха до ≥40 работа возобновляется в следующем доступном `WORK`.
   Назначить свободную достижимую кровать через «Дом здесь» или `/knpc sethome <id>`, стоя рядом с ней:
   теперь это регистрация HOME в MCA, а не только координаты Kingdom. Проверить настоящее положение лёжа,
   рост энергии и сохранение HOME после рестарта. `/knpc schedule` показывает график, активность и диагностику кровати.
   Не считать стояние у занятой/сломавшейся/недоступной кровати успешным сном. В TFC календарь может отменять
   обычное `/time set`; для теста использовать штатное управление календарём TFC либо ждать нужного периода.
6. Начислить реальный долг зарплаты через действующий договор. Выплатить медными монетами из инвентаря работодателя.
   Сверить монеты плательщика, личный физический кошелёк NPC и уменьшение долга. Повторная выплата при нулевом долге — отказ.
   Зарплата хранится в `wagePurse`, отдельно от сумки MCA; исторический кошелёк больше не копируется в сумку.
7. Штатно остановить и запустить сервер посреди смены. Сверить UUID, семью, NBT/прочность инструментов,
   количество монет, сумку, склад, слой шахты и отсутствие повторных заявок/наследства.
8. Выполнить контрольные задания фермером, лесорубом, кузнецом, строителем и курьером на существующих объектах;
   проверить банк, городские права и Книгу Королевства Stage 0.

## Границы безопасности

Покупки переводят точный физический набор номиналов продавцу; сдача и размен не выполняются.
Неизвестные обёртки контейнеров/двойные сундуки блокируются до доказательства независимости физических слотов.
После рестарта при наличии журнала `data/kingdom-resident-purchases` покупки блокируются до ручной сверки:
сопоставьте снимки `Before/After`, кошелёк NPC, сумку и сундук продавца. Не удаляйте журнал для обхода проверки.
Общего crash-atomic сохранения entity/chunk/SavedData нет; автоматический повтор сомнительного перевода запрещён.
При `InventoryRecoveryRequired` сохранены данные для сверки, работа и открытие сумки блокируются.
Не снимайте этот флаг без проверки обоих владельцев предметов и резервной копии.

Автоматический прогон описан в `validation/npc-runtime/README.md`. Он не подтверждает клиентские окна,
полную проходку шахты с реальной навигацией, все профессии и миграцию конкретного мира владельца.


## Дополнение к PR #107: индивидуальная жизнь MCA (25.11.2026)

Проверена реализация именно JAR MCA 7.7.1-beta.5: `SchedulesMCA`, `VillagerTasksMCA`,
`VillagerBrain`, `Residency` (JDK17 `javap -p -c`). Источник времени —
`resident.getBrain().getSchedule().getActivityAt(dayTime % 24000)`. Выборщик
`SchedulesMCA.getTypeSchedule` повторно бросает вероятность ночного жителя и для чтения не вызывается.
Учитываются реальные `MoveState` MOVE/STAY/FOLLOW и `Chore`: приказы MCA не перезаписываются.
При перестроении мозга MCA новая версия расписания и активности сохраняется.

Kingdom временно удерживает только рабочую активность CORE и WALK_TARGET; родной объект расписания,
HOME/JOB_SITE/MEETING_POINT, семейные данные и default activity остаются MCA.
Узкий Brain mixin откладывает смену активности лишь у арендованного мозга либо при вынужденном
нативном REST из-за критической усталости; PANIC/HIDE/RAID всегда приоритетнее.
Отдых KINGDOM_REST не владеет навигацией. Отдельный ограниченный выход из шахты не разрешает добычу;
при неудаче возвращается управление MCA с диагностикой EXIT_BLOCKED, без телепортации и прокладки нового пути.
Во время обычной жизни/отдыха городской контроллер движения Kingdom не подменяет путь MCA.

Энергия восстанавливается только по последовательным наблюдаемым тикам: +1 за 100 тиков настоящего сна
либо за 400 тиков неподвижного нативного REST. Хождение к кровати и выгрузка чанка не дают восстановления.
Порог усталости ≤25; сохранённая защёлка не даёт вернуться к работе раньше ≥40. Старые SavedData читаются
с прежними значениями и новым необязательным полем FatigueRestRequired=false.

Изменения этого дополнения не затрагивают алгоритм 7×7, инструменты, лестницы и TFC-добычу относительно
сохранённого коммита `f26b35a`. Полная автономная проходка породы пока не подтверждена: предыдущий
гранитный прогон остановился после 5 клеток второго слоя со статусом «Несёт крепления к опасному участку»
(позиция 39,198,42). Это известное ограничение кандидата, а не успешная приёмка всей шахты.

Заявленные 24.11 659 проверок действительно были результатом JUnit/Gradle (0 failures/errors/skips),
а не 659 игровых сценариев; первоначальный временный лог утрачен при перезапуске среды.
Новые результаты и точный артефакт публикуются в описании PR #107. Клиентские окна/визуальная игровая
приёмка и миграция конкретного мира владельца не проверены: клиент и копия этого мира не предоставлены.

Серверный сценарий индивидуальной жизни: реальные DEFAULT/NIGHT_OWL_DEFAULT, команды STAY/FOLLOW/Chore,
регистрация настоящей кровати через production-командный bridge, сон 1500 наблюдаемых тиков,
энергия 25→40 и самостоятельное пробуждение/возврат рабочей смены подтверждены на текущем наборе модов.
Это отдельный сценарий жизненного цикла, не доказательство безопасного выхода из глубокой шахты.
